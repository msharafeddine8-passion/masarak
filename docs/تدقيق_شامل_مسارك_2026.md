# تقرير التدقيق المؤسّسي الشامل — منصّة مسارك (Masarak)

**التاريخ:** 29 يونيو 2026
**النطاق:** الموقع الكامل (masaraklb.com) + الكود (Next.js 14 App Router) + قاعدة البيانات (Supabase Postgres) + SEO + الأمان + الأداء + UX/UI + المحتوى التعليمي + الأعمال
**المنهجية:** تدقيق قائم على الأدلة — قراءة فعلية للكود (~95 صفحة، ~17 API route، 81 جدول) واستعلامات مباشرة على قاعدة البيانات الإنتاجية ومستشاري Supabase (security + performance advisors). كل بند موثّق بمرجع `ملف:سطر`.

> **كيف تقرأ هذا التقرير:** ابدأ من **القسم 1 (الملخص + درجة الصحة)** ثم **القسم 2 (الـ 12 خطراً الحرجة — أصلِحها أولاً)**، ثم نفّذ حسب **خريطة الطريق في القسم 14**. باقي الأقسام مرجعية مفصّلة حسب التخصص.

## 1) الملخص التنفيذي ودرجة الصحة

مسارك منصّة **طموحة وغنيّة بالمزايا بشكل استثنائي** (95 صفحة، 81 جدولاً، أدوات DNA مهنية، نظام تلعيب، لوحات للأهل/المرشدين/المؤسسات). البنية التقنية الأساسية **أعلى من المتوسط** لمشروع ناشئ: RLS مفعّل على كل الجداول، ISR على كل صفحات الكيانات، sitemap ديناميكي، خطوط self-hosted، middleware يعتمد `app_metadata` للأدمن، وتصحيح خادمي لإجابات الكويز.

لكن المنصّة تعاني من **ثلاث مشاكل بنيوية متكرّرة** تظهر في كل تدقيق تقريباً:

1. **التجزئة (Fragmentation):** ~20 صفحة يتيمة، صفحات مكررة (`/tools/strengths`↔`/tools/skill-strengths`، DNA↔major-match، محلي↔عالمي للمنح)، 3 أنظمة ألوان متضاربة، ومصدرَا حقيقة متعارضان للرواتب.
2. **مشاكل النزاهة والثقة (Trust):** صور جامعات وهمية (picsum)، مراجعات مفبركة بأسماء، روابط منح ميتة (`link:"#"`)، مواعيد نهائية متقادمة كنصّ ثابت — هذه قاتلة لمنصّة "توجيه".
3. **الوعد غير المُنجَز (الفجوة المركزية):** كل البيانات موجودة (RIASEC + رواتب + كلفة + طلب + منح) لكنها **لا تُدمج أبداً** في إجابة واحدة شخصية على السؤال الجوهري للطالب: *«تخصّص يناسبني + له وظائف في بلدي + أقدر أتحمّل كلفته»*.

| المجال | الدرجة /10 | الحالة |
|---|---|---|
| البنية التقنية والأمان الأساسي | 6.5 | جيد مع ثغرة حرجة واحدة (daily-challenge) |
| هندسة المعلومات والمسارات (IA) | 4.0 | تجزئة شديدة |
| UX / حالات الأخطاء والتحميل | 4.5 | أخطاء تُخفى كـ"لا نتائج"، لا boundaries |
| UI / اتساق التصميم | 4.0 | 3 أنظمة ألوان + تضارب توكن |
| إمكانية الوصول (WCAG 2.2) | 4.5 | أساس جيد، فجوات منهجية |
| SEO تقني | 7.0 | الأقوى — مع فجوات schema/client-render |
| الأداء (Core Web Vitals) | 5.5 | صور خام + client-rendering للصفحات الرئيسية |
| المحتوى والجودة التعليمية | 4.5 | عميق هيكلياً، ضحل/مفبرك في أماكن |
| التوجيه المهني (الوظيفة الأساسية) | 4.0 | الأدوات موجودة، الـ"spine" مفقود |
| قاعدة البيانات والتوسّع | 6.0 | سليمة بنيوياً، تحتاج تحسين RLS/فهارس |
| **الإجمالي المرجّح** | **5.1 / 10** | **منصّة واعدة تحتاج "توحيد + تنظيف + ربط"** |

**التوصية الاستراتيجية الكبرى:** قبل إضافة أي ميزة جديدة، نفّذ **حملة توحيد وتنظيف (Consolidation Sprint)**: ادمج الصفحات المكررة، احذف اليتيمة والـ"قريباً"، أصلِح مشاكل الثقة، ووحّد نظام التصميم. ثم ابنِ **"العمود الفقري للقرار"** (Decision Spine) الذي يربط الأدوات في رحلة واحدة. هذا يرفع الدرجة من 5.1 إلى ~7.5 بأقل جهد نسبي.
